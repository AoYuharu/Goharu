发现的两个 Bug

Bug 1 — merge 把富内容覆盖成贫内容（信息丢失）

根因：_execute 里 update 和 merge 走同一分支，都用新上报的 name/desc 覆盖 target。

后果：merge 时原有原子的富描述（多音色、语速调节）被稀疏重复项覆盖。

Bug 2 — retire 和 update 指向同一原子时，retire 被静默撤销

根因：先 retire_capability（status=retired），随后 upsert_capability 又把 status 改回 active。

后果：retire 白做，日志留下误导性 retire 事件。

修复验证

修复 Bug 1 — merge 保留现有富内容，仅记录事件

确定性注入 merge 决策后，tts 名称/描述/版本均保持不变，且不产生多余的 voice-broadcast 行。

capability名称状态版本描述
merge-test-01/tts语音合成activev1把文字转成自然流畅的语音播报，支持多音色切换和语速调节

事件日志：tts / add → tts / merge（merge 落在 target 上，内容未变、版本未 +1）。

修复 Bug 2 — retire 过滤掉"正在更新的原子本身"

新版上报后，旧原子干净地原地演化，事件日志不再有误导性 retire。

capability名称状态版本描述
fix-verify-01/speech-rec-old语音识别新版activev2支持中英文实时转写，准确率高，替代旧版方案

事件日志：speech-rec-old / add → speech-rec-old / update（无 retire）。

结论

4 个 curator 动作（add / update / merge / ignore）+ 名字/能力双路检索全部跑通； 两个边界 bug（merge 信息丢失、retire 与 update 冲突）已修复并验证。 唯一需注意：curator 的 LLM 判断非确定性，同一份上报可能时而判 add、时而判 merge， 去重是"大概率对"而非"必然对"。
