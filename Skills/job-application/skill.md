# 岗位投递流程（Job Application）

目标：把用户的简历投到指定公司（如"投一下公司 A 的 XX 岗位"）。全程遵守
base.md 的「Web 操作纪律」（看到≠验证过、不猜 URL、不编造页面障碍）。

## 阶段 0：定位投递入口

1. 用 `mcp__tavily__tavily_search` 搜索「公司 A 招聘官网 / 校招 / careers」。
   **优先公司官方招聘站**；官网找不到或需要聚合平台时才用 BOSS 直聘等第三方。
2. 进入官网后**走站内 UI 找到职位列表/搜索页**，不要手拼 URL 参数。
3. 若官网是第三方招聘 SaaS（moka/北森等），记住它的域名特征，后续表单模式类似。

## 阶段 1：明确岗位需求

到人才搜索/职位列表页，先和用户确认要投的**岗位类型**：

- 实习（日常实习 / 应届实习）
- 实习转正 / 管培生
- 正式岗位（校招/社招）

**筛选复选框**：职位列表页通常有筛选条件（实习/校招/社招、工作地点等），
进页先找有没有这类复选框——要投实习就先勾"实习"，能显著缩小列表。

**甄别实习类型（拿不准必问）**：应届实习（毕业前、转正导向）、校园实习
（校招通道）、日常实习（随时到岗、时长灵活）三者门槛与转正差异很大。
页面上分不清是哪类、或用户没明说时，**必须问用户**具体投哪类，不要猜。

**工作地点**：筛选和填表都涉及地点（北京/上海/广州/深圳等）——按用户
记忆里的偏好城市选；没有记录或拿不准就问，不要默认替用户决定。

读清楚目标岗位的 JD 硬性要求，与用户背景（可 `memory_search` 查简历/偏好记忆）
做匹配度评估，**不匹配的直接跳过**，不要自作主张投不合适的岗。

**学历要求过滤（硬性）**：看清岗位的学历门槛——只招硕士/博士的岗位，
本科用户**直接跳过不投**（不达标投了也是浪费名额）；按用户实际学历
（memory 里有：本科/硕士/博士）只投允许该学历及以下的岗位。不确定学历要求时
先查 JD 原文，查不到就不投并告知用户。

**批量投递策略（不是只投一个）**：先弄清该公司/平台**最多同时可投几个岗位**
（见下方红线区），然后按限额**搜集足额的匹配岗位**（比如限额 3 个就找 3 个
都合适的），**全部投递**——不是从一堆岗位里只挑一个最匹配的。匹配度可以
有高低，但都要过硬性门槛（学历/毕业年份/到岗要求）。限额内凑不满合适岗位时
如实告诉用户"只找到 N 个达标的"，不要硬凑不合适的。

## 阶段 2：登录

- **首选微信扫码登录**：点击微信登录入口，把二维码页面留在屏幕上，提示用户扫码，
  等用户确认"扫好了"再继续。
- 也可手机验证码登录：需要用户手机号时先 `memory_search` 查记忆（查不到再问用户，
  不要断言"没有存过"）；验证码必须由用户提供，**绝不猜测**。
- 登录后用 `browser_inspect` 确认登录态（登录按钮消失/头像出现）才算完成。

## 阶段 3：登录后的两件必查事项

**3a. 简历完备性检查**——进入"我的简历/在线简历"页面：

- 检查个人信息、教育背景、实习/工作经历、项目经历是否已完整。
- 平台没有简历或信息不全时，**补齐再投**：从 `memory_search` 和本地简历文件
  （Desktop/研究生/简历.pdf、Desktop/面试/简历.pdf，可用 parse_pdf 读）取内容填写。
- 简历自动解析填充的字段**视为未验证**——每个字段要点开/回读确认值真的写对。

**简历编辑页两阶段填表法（重要，照此执行）：**

**阶段一：侦察——先摸透整页，参数一次收集齐，禁止边填边查**

1. **上下滚动浏览整个编辑页**（懒渲染内容滚到才出现），把所有要填的栏位看全，
   不要看了一半就开始填。
2. 有**添加按钮**的折叠栏位（教育/实习/项目/工作经历）先点＋把栏位加够
   （两段实习就加两个栏位），了解每个栏位内的控件结构。
3. 整页了解完后，**把所有填写参数一次性全部获取出来并存进上下文**
   （记不住就写临时脚本/文件存参数表）：
   - 每个待填控件的 **index 索引值**
   - 每个控件的**类型与选项**（下拉的完整选项列表、文本框、单选/多选；
     下拉要打开才能看到选项——原生 `<select>` 除外）
   - **日期控件的填写方式**（年/月各自是下拉还是输入框？怎么触发选项？）
   - 每个字段**应该填什么值**（对照简历内容定好）
4. 侦察完成的标准：说得出"第 N 个控件是 X 类型、index 是 Y、选项是 Z、应填 W"。
5. **填写前查一次页面指纹**：`browser_inspect(fingerprint=true)` 记下 form_sig——
   页面若有自动保存/重渲染导致结构变化，指纹会告诉你 index 已失效需重新侦察。

**阶段二：一口气填写 + 最后统一校验**

6. 基于阶段一的参数表，**连续调用、一口气把全部字段填上去**——
   禁止填一格就停下来 get_state 查一格；中间某格失败先记下、继续填后面的，
   最后统一处理失败的格子。
7. 全部填完后，**再滚动全页做一次整体校验**（browser_inspect / get text），
   逐字段对照"应填值 vs 实际值"，有错的修正后复核该字段。
   （填写本身会改变指纹，此时不需要再查 fingerprint——校验以实际回读为准。）
   填写过程中可随时用 **`browser_showdiff`** 查看页面相对上一次 inspect 的变化
   （值变了哪些、新增了弹层/错误提示、组件消失），比整页重读便宜得多。
8. 校验通过才进入投递。

**3b. 历史投递记录检查**——进入"我的投递/申请记录"页面：

- 查该公司（以及用户提到过的其他公司，如字节、阿里、腾讯）已投过哪些岗位。
- 已投的岗位：流程是否关闭（挂了/结束）、还是仍在进行中。
- **正在流程中的岗位不重复投**；已关闭的可以再投（若名额允许）。

## 阶段 4：填表与投递

1. 回到目标岗位点"申请/投递"，逐项填表（见下方注意事项）。
2. 填完后**逐项复核**再预览，最终"确认提交"前把摘要给用户过目
   （含岗位名、简历版本、关键表单值），用户点头后才提交。
   名额有限的平台（如 moka 类 3 个月限 3 个）明确提醒用户"这次投递会占用 1 个名额"。

## 红线与注意事项

### 投递名额限制——零幻觉红线

每个平台/公司**同时允许投递多少个岗位**（如"3 个月内限投 3 个职位"）必须在投递前
**弄清楚并告知用户**，并据此执行批量投递策略（按限额搜足岗位、全部投递）。
查清途径（按优先级）：

1. 申请页/职位页上的明文提示（如"3个月内限投3个职位"）
2. 站内帮助/FAQ
3. Tavily 搜「平台名 + 投递数量限制」

**查不到就是查不到，如实告诉用户"没查到限制说明"，绝不猜一个数字。**
投递名额直接消耗用户的机会，这条信息幻觉的代价不可挽回。

### 折叠栏位（经历类表单）

- 不同公司的简历编辑页结构不同；工作经历/教育背景/项目经历/实习经历常见**折叠卡片**，
  右上角有加号（＋添加一条）/减号（－删除一条）。
- 用户有两段实习就要点＋**添加第二个栏位**再填内容，不要把两段塞进一格。
- 栏位加够属于**阶段一（侦察）**的动作——先把所有栏位展开、收集完参数再批量填。
- 填写一律按上面的「两阶段填表法」执行：先全收集、后一口气填、最后统一校验。

### 文件上传——转人工

**没有任何文件上传工具。** 需要上传简历/附件时：

1. 用 `browser_click` 点"上传简历/上传附件"按钮，**让文件选择框弹出并留在屏幕上**；
2. 明确告诉用户："文件选择框已打开，请你选择本地文件（建议 Desktop/研究生/简历.pdf）"；
3. 用户传完后用 `browser_inspect` 确认文件名出现在页面上，再继续。
   不要尝试用脚本/CDP 绕过上传（历史尝试均已失败或引入断连事故）。

### 验证码/人机验证

滑块拼图、图形验证码等一律**请用户手动完成**，完成后告诉你。自动盲拖会触发风控。
绝不允许编造"有验证码挡着"——页面没有验证码时如实报告实际状态。

### 收尾

- 投递成功后记录：公司、岗位、时间、平台、返回的 candidateId 等凭据
  （`memory_add` 一条简明原子）。
- 临时脚本（tmp_*.py）用完即删。
