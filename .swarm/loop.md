- 2026-10-31｜**MCP 全员挂死根因：anyio 结构化并发宿主任务早逝**。现象：守护启动时 list_tools 正常（5 tools connected），之后任何 CallTool 请求**永远写不进子进程 stdin**（子进程 stderr 只有 ListToolsRequest，0 次 CallToolRequest），前台挂满 background_timeout 转后台后永不返回；manager 层 wait_for 超时也救不了（anyio task group 的取消同样跨任务失效）。根因：MCP 会话（stdio_client/ClientSession 的 anyio task group）是在 `loop.run_until_complete(_manager.start())` 的**宿主任务**里进入的，run_until_complete 返回即宿主任务结束 → task group 半坏（同一任务内建立的启动期调用还能跑，之后的全部写不通）。这也是一直在日志里刷 "Attempted to exit cancel scope in a different task" 的真正来源。修法：事件循环放独立线程 run_forever，**一个常驻根协程** start → 等停止信号 → shutdown（进入/退出同一任务）；队列/请求仍走主线程 + run_coroutine_threadsafe。验证：music_search 从 120s 挂死 → **581ms 成功**（agent 自检拿到真实歌单）。教训：**任何包裹第三方 anyio/asyncio 资源的长生命周期服务，宿主任务必须与资源同生共死**——run_until_complete 只适合"进+出全包"的一次性操作。
